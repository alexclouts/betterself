L'architecture actuelle de BetterSelf

L’architecture actuelle de BetterSelf

Après avoir comparé différentes possibilités, une première architecture technique se dégage pour BetterSelf.

Ces choix ne sont toutefois pas tous définitifs. Le développement du prototype permettra de valider ou de remettre en question certaines des décisions prises au départ.

Les choix actuels

Composant Technologie
Frontend React
Interface mobile Progressive Web App
Backend Python + FastAPI
Validation Pydantic
Accès aux données SQLAlchemy
Base de données initiale SQLite
Base de données potentielle PostgreSQL
Conteneurisation Docker
Hébergement backend envisagé Railway
Hébergement frontend envisagé GitHub Pages
API alimentaire Open Food Facts

Architecture envisagée

L’application devrait suivre une architecture séparant clairement le frontend, le backend et la base de données.

                    ┌──────────────────┐
                    │     Utilisateur  │
                    │ Mobile / Desktop │
                    └────────┬─────────┘
                             │
                             ▼
                    ┌──────────────────┐
                    │   React / PWA   │
                    └────────┬─────────┘
                             │ HTTP
                             ▼
                    ┌──────────────────┐
                    │     FastAPI      │
                    │     Backend      │
                    └──────┬─────┬─────┘
                           │     │
                     SQL   │     │ HTTP
                           │     ▼
                           │  Open Food
                           │    Facts
                           ▼
                    ┌──────────────────┐
                    │      SQLite      │
                    │  → PostgreSQL    │
                    └──────────────────┘

Cette séparation permettra notamment au frontend de rester indépendant de la technologie utilisée pour stocker les données.

Elle devrait également faciliter l’évolution de l’application. Par exemple, une migration de SQLite vers PostgreSQL ne devrait pas nécessiter de réécrire l’interface React.

Une architecture qui évoluera

Cette architecture représente l’état actuel de ma réflexion et non une spécification définitive.

Certains choix seront validés uniquement lorsque les premières fonctionnalités fonctionneront réellement.

C’est notamment le cas de l’hébergement, de l’authentification, de la gestion des états dans React et de la stratégie de cache pour Open Food Facts.

L’un des objectifs de ce blogue sera justement de documenter ces changements.

Si une décision prise aujourd’hui s’avère inadéquate plus tard, je pourrai revenir sur le raisonnement initial, expliquer le problème rencontré et documenter la solution retenue.

C’est aussi une façon de transformer le développement de BetterSelf en une expérience d’apprentissage documentée plutôt qu’en une simple succession de fonctionnalités.
